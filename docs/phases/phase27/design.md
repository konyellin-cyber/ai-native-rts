## 一句话目标

Phase 27 不直接扩展玩法系统，而是先演练一条稳定的 Phase 26 士兵美术生产流水线：

> 从 45 度人体 / 枪兵透视构造线稿开始，先确认视角、比例、地面关系和武器方向正确，再逐步生成姿态表、装备轮廓、色块测试和 sprite atlas 方案，并保存每一步 prompt、输入、输出和修正记录。

目标不是一次生成最终素材，而是验证：能否用可复用流程稳定产出适合人海阵线战的士兵美术。

---

## 背景

Phase 26 已经把重点放在阵线力学、人海密度和性能上。下一阶段会需要大量士兵视觉实例，如果直接生成成品图，容易出现：

- 视角不稳定：同一兵种不同图的透视角度不一致。
- 人体比例漂移：头身比、肩宽、腿长在不同动作之间变化。
- 装备轮廓不稳定：盾、矛、甲胄在小尺寸下不可读。
- 风格漂移：线条、材质、色彩在批量生成时逐渐偏离。
- 无法复现：只保存图片，不保存 prompt 和失败原因，后续难以迭代。

因此 Phase 27 先建立流水线和记录规范，把“稳定性”放在流程上，而不是寄托在某个单次 prompt 上。

---

## 核心原则

### 1. 先锁视角和比例，再谈美术完成度

第一步只生成类似素描的构造线稿：人体体块、关节轴线、地面接触点、武器方向线和 45 度透视辅助线。

这一张图的用途是母版，不是最终素材。它必须锁定：

- 45 度 RTS / 等距近似视角。
- 头身比。
- 肩宽、躯干、腿长比例。
- 站姿重心。
- 透视压缩程度。
- 脚底和地面的接触关系。
- 长枪在地面平面上的方向。
- 缩小到战场尺寸后的可读性。

透视母版未通过评审前，不允许进入装备细节、色块或动作 sheet。

### 2. 先线稿，后轮廓，再色块

流水线顺序固定为：

```text
人体 / 枪兵透视构造线稿基准
↓
核心动作姿态表
↓
装备轮廓层
↓
材质与家族色块层
↓
sprite atlas / impostor 输出方案
↓
Godot 小规模窗口验证
```

任何一步不稳定，不进入下一步。

### 3. 少量高一致性素材 + 程序化变化

Phase 26 的人海表现不应该依赖大量独立生成图。

更合适的策略是：

- 先产出少量高一致性士兵 atlas。
- 在 Godot 中通过随机帧偏移、轻微缩放、朝向变化、家族色 tint、队列密度变化制造差异。
- 避免每个士兵实例都需要独立美术图。

### 4. Prompt 是版本化资产

每一步 prompt 都必须保存。保存内容包括：

- 本步骤目标。
- 正向 prompt。
- 负向 prompt / 禁止项。
- 输入参考图。
- 输出文件路径。
- 结果评价。
- 失败原因。
- 下一步修正计划。

## 流水线步骤

### Step 1：人体 / 枪兵透视构造线稿基准

目标：得到一个适合作为 Phase 26 士兵母版的 45 度透视构造线稿。

要求：

- 单个枪兵人体。
- 可以持一根简化长枪，但长枪必须是透视辅助线性质，不做成品武器细节。
- 45 度 RTS / 等距近似视角。
- 站姿稳定，重心清楚。
- 线条类似素描 / 动画设定稿 / construction drawing。
- 显示头部、胸腔、骨盆、四肢的体块关系。
- 显示脚底落点、地面椭圆或地面网格。
- 显示长枪在地面平面上的方向线。
- 白底或浅灰底。
- 不要上色，不要材质，不要阴影，不要厚涂。

验收：

- 视角适合放进 45 度战场。
- 能看出头、躯干、骨盆、腿和脚底如何落在地面上。
- 长枪方向符合 Phase 26 阵线接触的地面方向，不像横版侧视武器。
- 作为后续姿态和装备的比例母版不会显得畸形。
- 通过 review 后才能进入 Step 2。

### Step 2：核心动作姿态表

目标：在同一人体比例和视角下生成 4–6 个基础动作。

首批动作：

- idle
- march
- attack
- brace / hold line
- hit / stagger
- fallen

验收：

- 每个动作头身比一致。
- 角色朝向一致。
- 动作缩小后可区分。
- 没有明显风格漂移。

### Step 3：装备轮廓层

目标：在线稿基础上叠加中世纪轻甲士兵轮廓。

首批装备：

- 轻甲步兵。
- 矛兵。
- 盾兵。
- 旗手 / 将领标记。

验收：

- 缩小后能通过轮廓区分兵种。
- 盾、矛、旗帜不遮挡人体重心。
- 装备不破坏 Step 1 的视角和比例。

### Step 4：材质与色块层

目标：验证士兵在低饱和色块下的可读性。

原则：

- 家族色主要放在旗帜、盾面、披布或腰布。
- 不把整个人涂成纯家族色。
- 金属、皮革、布料只做大块区分，不追求近景细节。
- 小尺寸下轮廓优先于材质细节。

验收：

- 远景可读。
- 三个家族 tint 后仍然能区分单位和装备。
- 不出现过亮、过花、过写实导致人海画面噪声过高。

### Step 5：Atlas / Impostor 输出方案

目标：定义可被 Phase 26 批量渲染使用的素材组织方式。

建议：

- 每个兵种 1 张 atlas。
- 每个动作 4–8 帧。
- 先支持 1 个主要朝向，后续再扩到多朝向。
- 保留透明背景版本。
- 命名包含兵种、动作、版本号。

示例：

```text
soldier_light_infantry_v001.png
soldier_spearman_v001.png
soldier_shieldman_v001.png
```

## Prompt 记录模板

每个 prompt 文件使用以下结构：

```markdown
# 001 Body Perspective Lineart

## Goal

本步骤要验证什么。

## Positive Prompt

实际使用的正向 prompt。

## Negative Prompt

禁止项和容易漂移的内容。

## Input References

使用了哪些参考图或上一步输出。

## Output

输出文件路径。

## Review

结果是否通过，哪里不稳定。

## Next Revision

下一次怎么改 prompt 或参考图。
```

## 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 视角漂移 | 批量生成时角度变成正面、侧面或俯视 | 每步都引用 Step 1 母版，并在 review 中检查角度 |
| 比例漂移 | 不同动作头身比变化 | 姿态表阶段只接受同一比例的输出 |
| 细节过密 | 人海缩小后画面变脏 | 先做线稿和大色块，不提前追求材质 |
| prompt 不可复现 | 只有图，没有上下文 | 每步强制保存 prompt、输出和 review |
| atlas 不适配引擎 | 生成图好看但不好切帧 | Step 5 单独定义 atlas 尺寸、帧数和命名 |

## 成功标准

1. 完成 1 张人体 / 枪兵 45 度透视构造线稿基准图。
2. 完成 1 张 4–6 动作线稿姿态表。
3. 完成 1 张轻甲士兵装备轮廓测试。
4. 完成 1 张低饱和色块测试。
5. 每一步都有对应 prompt 记录。
6. 每一步都有 review，明确是否可进入下一步。
7. 至少一张输出图被用于 Phase 26 小规模窗口验证或 mock 验证。

---

## 非目标

- 不在本阶段制作完整兵种库。
- 不在本阶段替换 Phase 26 的全部士兵渲染。
- 不追求最终商业美术质量。
- 不为每个士兵实例生成独立图片。
- 不同时推进 Phase 2 RTS 沙盒玩法。
